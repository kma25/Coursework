# Тестовые сценарии и структура проверок

## Найденные и исправленные проблемы

- Часть проверок прав доступа была покрыта только ручным запуском команд, без unit-тестов.
- Роль `statistician` могла обращаться к сервису заметок на уровне бизнес-логики, хотя по требованиям она должна работать только со статистикой.
- Тестовые параметры для нескольких сценариев были зашиты в код тестов, поэтому их сложнее было показать как полноценные тест-кейсы.
- Для GitHub Releases был риск принять архив исходников за готовую сборку приложения; это уже закрыто отдельной проверкой.
- `Watcher` был вынесен в отдельный проект, но теперь запускается из `MainApp` автоматически в фоновом режиме.

## Структура тестового проекта

```text
AppTests/
├─ Data/
│  └─ test-input-data.xml
├─ AccessControlTests.cs
├─ AuthServiceTests.cs
├─ ConfigurationTests.cs
├─ NoteServiceTests.cs
├─ UpdateServiceTests.cs
├─ Fakes.cs
└─ XmlTestData.cs
```

Тестовый проект `AppTests` подключен к `Coursework.sln` и ссылается на `MainApp`. Основные проекты не зависят от тестового проекта.
В проекте оставлен MSTest, потому что он ближе к выбранному учебному шаблону Visual Studio. Сейчас набор содержит 21 автоматическую проверку.

## XML-данные

Файл `AppTests/Data/test-input-data.xml` содержит группы:

- `authorization` - пары логин/пароль для параметризованного теста входа;
- `registration` - регистрационные сценарии;
- `database` - параметры строк подключения;
- `notes` - данные для заметок;
- `roleAccess` - проверки ролей и прав доступа;
- `updates` - ответы GitHub Releases и ошибки обновлений.

## Основные тест-кейсы

| Группа | Сценарий | Ожидаемый результат |
|---|---|---|
| Авторизация | корректный логин и пароль | вход успешен |
| Авторизация | неверный пароль | вход запрещен |
| Заметки | пустая заметка | заметка не создается |
| Заметки | обычный пользователь редактирует чужую заметку | доступ запрещен |
| Заметки | администратор редактирует чужую заметку | доступ разрешен |
| Права доступа | статистик просматривает мониторинг | доступ разрешен |
| Права доступа | обычный пользователь просматривает мониторинг | доступ запрещен |
| Права доступа | статистик создает, редактирует или удаляет заметку | доступ запрещен |
| Права доступа | администратор удаляет чужую заметку | доступ разрешен |
| Права доступа | статистик создает пользователя | доступ запрещен |
| Права доступа | администратор создает пользователя | доступ разрешен |
| Обновления | релиз содержит ZIP в Assets | обновление найдено |
| Обновления | релиз содержит только source zip | установка запрещена |
| Обновления | GitHub API вернул ошибку | ошибка обработана контролируемо |

## Пример XML-кейса

```xml
<roleAccess>
  <case name="statisticianCanViewMonitoring"
        role="statistician"
        deviceName="DEV-WORKSTATION-01"
        metricsCount="3"
        success="true" />
</roleAccess>
```

## Зачем внесены изменения

Изменения делают проект ближе к требованиям курсовой: тесты разделены по смыслу, параметры вынесены в XML, роль статистика проверяется отдельно, а комментарии и структура проекта лучше объясняют назначение компонентов.
