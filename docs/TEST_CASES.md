# Тестовые сценарии и структура проверок

## Найденные и исправленные проблемы

- Часть проверок прав доступа была покрыта только ручным запуском команд, без unit-тестов.
- Роль `statistician` могла обращаться к сервису заметок на уровне бизнес-логики, хотя по требованиям она должна работать только со статистикой.
- Тестовые параметры для нескольких сценариев были зашиты в код тестов, поэтому их сложнее было показать как полноценные тест-кейсы.
- Отдельные классы `AccessControlTests` и `ConfigurationTests` создавали лишние группы в Test Explorer. Проверки перенесены в четыре основные группы задания.
- Для GitHub Releases был риск принять архив исходников за готовую сборку приложения; это уже закрыто отдельной проверкой.
- `Watcher` был вынесен в отдельный проект, но теперь запускается из `MainApp` автоматически в фоновом режиме.

## Структура тестового проекта

```text
AppTests/
├─ Data/
│  └─ test-input-data.xml
├─ AuthorizationTests.cs
├─ NotesTests.cs
├─ DatabaseTests.cs
├─ GitTests.cs
├─ Fakes.cs
└─ XmlTestData.cs
```

Тестовый проект `AppTests` подключен к `Coursework.sln` и ссылается на `MainApp`. Основные проекты не зависят от тестового проекта.
В проекте оставлен MSTest, потому что он ближе к выбранному учебному шаблону Visual Studio. Сейчас набор содержит 4 тестовых класса и 21 автоматическую проверку.

## XML-данные

Файл `AppTests/Data/test-input-data.xml` содержит группы:

- `authorizationLogin` - пары логин/пароль, роли и состояние блокировки;
- `authorizationRegistration` - регистрационные сценарии;
- `notesAdd` - входные данные для добавления заметок;
- `notesEdit` - владельцы, роли и новый текст для редактирования;
- `databaseConnection` - параметры строк подключения;
- `gitUpdates` - полные XML-наборы ответов GitHub Releases, включая JSON тела ответов.

## Основные тест-кейсы

| Группа | Сценарий | Ожидаемый результат |
|---|---|---|
| Авторизация | корректный логин и пароль | вход успешен |
| Авторизация | неверный пароль | вход запрещен |
| Авторизация | заблокированный пользователь | вход запрещен |
| Авторизация | первый пользователь регистрируется | получает роль admin |
| Авторизация | статистик регистрируется | получает роль statistician |
| Заметки | пустая заметка | заметка не создается |
| Заметки | статистик создает заметку | доступ запрещен |
| Заметки | владелец редактирует свою заметку | доступ разрешен |
| Заметки | обычный пользователь редактирует чужую заметку | доступ запрещен |
| Заметки | администратор редактирует чужую заметку | доступ разрешен |
| База данных | auth-подключение собирается из XML-настроек | строка подключения корректна |
| База данных | строка роли дополняется Host/Port/Database | строка подключения корректна |
| База данных | рабочая учетная запись postgres | подключение запрещено |
| Гит | релиз содержит ZIP в Assets | обновление найдено |
| Гит | версия уже актуальна | обновления не найдены |
| Гит | релиз содержит только source zip | установка запрещена |
| Гит | GitHub API ограничил запросы | ошибка обработана контролируемо |

## Пример XML-кейса

```xml
<notesEdit>
  <case name="обычный пользователь не редактирует чужую заметку"
        ownerId="1"
        actorId="2"
        actorRole="user"
        noteText="Чужая заметка"
        newText="Попытка изменения"
        expectedSuccess="false"
        expectedMessage="Нельзя изменить чужую заметку." />
</notesEdit>
```

## Зачем внесены изменения

Изменения делают проект ближе к требованиям курсовой: тесты разделены на четыре понятные группы, входные параметры и ожидаемые результаты вынесены в XML, а каждый запуск теста выводит в Test Explorer название набора, ожидаемый результат, фактический результат и сообщение сервиса.
