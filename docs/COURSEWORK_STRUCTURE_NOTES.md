# Ориентиры по пояснительной записке

Я просмотрел файл `Попович Тестирование (2).docx` как пример оформления курсовой. Это большая пояснительная записка: около 1255 текстовых абзацев, 22 таблицы, 16 рисунков/вставок и 3 секции документа.

Полезная структура, которую стоит взять за основу для своей записки:

1. Титульный лист.
2. Оглавление.
3. Введение.
4. Описание проекта и предметной области.
5. Техническое задание.
6. Схема декомпозиции технического задания.
7. Тест-кейсы для основных функций.
8. Код unit-тестов.
9. Общий отчет о тестировании.
10. Разработка проекта с использованием Git.
11. Заключение.
12. Список использованных источников.

Что видно по стилю работы:

- Текст написан не только про код, но и про предметную область: зачем нужна система, кто пользователи, какие риски.
- ТЗ разбито на функциональные и нефункциональные требования.
- Декомпозиция связывает требования с модулями системы.
- Тест-кейсы оформлены отдельным разделом, а код unit-тестов идет после них.
- Есть отдельный раздел про Git и GitHub Releases.

Для нашего проекта это значит: код уже есть, но для самой курсовой записки еще нужно оформить документ примерно по этой структуре.
