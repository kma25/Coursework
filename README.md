# Coursework

`Coursework` - консольная система для контроля небольшой ИТ-инфраструктуры VPN-сервиса. Приложение помогает вести служебные заметки, работать с пользователями, просматривать данные мониторинга устройств и проверять наличие обновлений через GitHub Releases.

Проект написан на C# и использует PostgreSQL для хранения данных. Интерфейс выполнен в виде консольного клиента, поэтому систему можно запускать на рабочем компьютере администратора или на сервере без графической оболочки.

## Назначение

Система предназначена для ситуаций, когда администратору нужно быстро зафиксировать служебную информацию, проверить состояние устройства или управлять доступом пользователей. В приложении объединены основные операции, которые могут понадобиться при сопровождении небольшой инфраструктуры:

- регистрация и вход пользователей;
- разграничение доступа по ролям;
- создание, просмотр, поиск, редактирование и удаление заметок;
- просмотр данных мониторинга CPU, RAM и HDD;
- ведение журнала событий безопасности;
- проверка и установка обновлений приложения;
- автоматический запуск фонового watcher-агента.

## Роли пользователей

В системе предусмотрены три роли. Набор доступных команд зависит от роли пользователя.

| Роль | Назначение | Доступ |
|---|---|---|
| `user` | Обычный пользователь | Может работать со своими заметками |
| `statistician` | Пользователь для просмотра статистики | Может просматривать только данные мониторинга |
| `admin` | Администратор системы | Имеет доступ к пользователям, заметкам, мониторингу и журналу безопасности |

Первый зарегистрированный пользователь автоматически получает роль `admin`. Это позволяет начать работу без отдельного создания администратора вручную.

## Состав решения

| Проект | Для чего нужен |
|---|---|
| `MainApp` | Основное консольное приложение, через которое пользователь работает с системой |
| `SystemWatcher` | Фоновый модуль, который собирает показатели CPU, RAM и HDD |
| `AppInstaller` | Установщик обновлений, который заменяет файлы приложения при наличии новой версии |
| `AppTests` | Отдельный проект с unit-тестами MSTest |
| `database` | SQL-скрипты для подготовки базы данных PostgreSQL |
| `docs` | Команды, тест-кейсы, схемы и материалы для пояснительной записки |

## Требования для запуска

Перед запуском должны быть установлены:

- Windows;
- .NET 8 SDK;
- PostgreSQL;
- pgAdmin или другой клиент для работы с PostgreSQL;
- Git, если проект запускается из локального репозитория;
- доступ к интернету, если требуется проверка обновлений через GitHub.

## Подготовка базы данных

Перед первым запуском нужно создать базу данных PostgreSQL и выполнить SQL-скрипт:

```text
database/create_database.sql
```

В текущей конфигурации основное приложение использует базу:

```text
Coursework tester
```

Для тестов рекомендуется использовать отдельную базу:

```text
Coursework test bsses
```

Подробная инструкция по настройке через pgAdmin находится в файле:

```text
docs/PGADMIN_SETUP.md
```

## Запуск приложения

Сначала нужно собрать решение:

```powershell
dotnet build Coursework.sln
```

После сборки основное приложение запускается командой:

```powershell
dotnet run --project MainApp
```

При старте приложение:

1. проверяет подключение к базе данных;
2. запускает `SystemWatcher` в фоновом режиме;
3. проверяет наличие обновлений;
4. выводит меню входа, регистрации и выхода.

Отдельно запускать watcher обычно не требуется. Он стартует вместе с `MainApp`, если в конфигурации включён параметр `AutoStartWatcher`.

## Работа с приложением

После входа можно ввести команду:

```text
help
```

Она показывает список команд, доступных текущему пользователю.

### Заметки

```text
nt add "текст"
nt list
nt recent [количество]
nt edit <id> "новый текст"
nt del <id>
nt search "текст"
```

Обычный пользователь работает только со своими заметками. Администратор может просматривать и редактировать заметки других пользователей через команды `admin nt`.

### Мониторинг

```text
watch list
watch status
watch show <имя ПК> [количество]
```

`watch list` показывает устройства, по которым есть данные мониторинга. Имя устройства из этого списка можно использовать в команде `watch show`.

### Обновления

```text
update check
update apply
```

`update check` проверяет наличие новой версии в GitHub Releases.  
`update apply` запускает установщик, если для новой версии доступен ZIP-архив готовой сборки.

### Администрирование

```text
admin user list
admin user create <логин> <пароль> [роль]
admin user info <логин>
admin user block <логин>
admin user unblock <логин>
admin user delete <логин>
admin nt view <id>
admin nt edit <id> "новый текст"
sec logs [количество]
```

Эти команды доступны пользователю с ролью `admin`.

## Мониторинг устройств

`SystemWatcher` собирает данные о загрузке процессора, использовании оперативной памяти и заполненности диска. Данные сохраняются в PostgreSQL и затем отображаются в основном приложении через команды `watch`.

Отдельный запуск watcher нужен только для проверки или отладки:

```powershell
dotnet run --project SystemWatcher -- --config SystemWatcher\watcher.yml
```

## Обновления приложения

Проверка обновлений выполняется через релизы репозитория:

```text
https://github.com/kma25/Coursework
```

Для обновления нужен ZIP-архив готовой сборки приложения. Архивы исходного кода GitHub не используются как готовое обновление.

## Тестирование

Тесты находятся в отдельном проекте:

```text
AppTests
```

Тестовые данные вынесены в XML-файл:

```text
AppTests/Data/test-input-data.xml
```

Запуск тестов:

```powershell
dotnet test Coursework.sln
```

Тестовый проект проверяет авторизацию, регистрацию, работу с заметками, права доступа, формирование строки подключения к базе данных и обработку ответов GitHub Releases.

## Полезные материалы

- `docs/figures` - схемы и рисунки для пояснительной записки;
- `database/README.md` - пояснение по SQL-скриптам.

## Назначение репозитория

Репозиторий содержит исходный код консольного приложения, фоновый модуль мониторинга, установщик обновлений, SQL-скрипты, тестовый проект и материалы для оформления курсовой работы. Его можно использовать для запуска системы, проверки её работы и демонстрации реализованных функций.
